# CharonCut

Самостоятельный браузерный видеоредактор с интерфейсом в духе CapCut. Это **не официальный продукт CapCut и не его полная копия**. Приложение статическое: сервер и сборка JavaScript для работы не нужны; медиа обрабатываются в браузере пользователя.

## Что есть

- Импорт поддерживаемых браузером видео, изображений и аудио; медиатека и таймлайн с основной дорожкой, наложением, текстом и аудио.
- Перемещение, обрезка, разделение, дублирование, удаление, отмена и повтор; регулировка масштаба таймлайна.
- Текстовые пресеты и стикеры, фильтры, несколько переходов, управление скоростью, громкостью и параметрами кадра.
- Форматы 16:9, 9:16, 1:1 и 4:5, предпросмотр и экспорт видео через MediaRecorder, а также сохранение кадра PNG.
- Автосохранение проекта в localStorage, исходников — в IndexedDB этого браузера. Проект можно скачать в JSON.

## Как начать

1. Откройте сайт в актуальном браузере на телефоне или компьютере; возможности браузеров и кодеки отличаются.
2. Нажмите **Импорт** или перетащите файлы в окно. Выберите клип на таймлайне, чтобы изменить его параметры справа.
3. Перетащите клип для перемещения, его край — для обрезки. Кнопка **Разделить** разрезает выбранный клип в позиции плейхеда.
4. На телефоне используйте кнопки **Инструменты** и **Параметры** под таймлайном, на компьютере — панели слева и справа. Добавьте текст, фильтры, переходы или звук. Нажмите **Экспорт** и скачайте готовый файл.

Горячие клавиши: пробел — воспроизведение, S — разрезать, Delete — удалить, Ctrl+Z / Ctrl+Shift+Z — отмена / повтор, Ctrl+S — сохранить, Ctrl+E — экспорт. Полный список — по кнопке `?` в редакторе.

## Публикация на GitHub Pages

1. Создайте репозиторий на GitHub и загрузите **всё содержимое** папки проекта, включая скрытую папку `.github`, в ветку `main`.
2. В репозитории откройте **Settings → Pages → Build and deployment → Source** и выберите **GitHub Actions**.
3. Откройте вкладку **Actions**: workflow `Deploy CharonCut to GitHub Pages` соберёт приложение и опубликует папку `dist`. Если он уже выполнился до изменения настройки Pages, запустите его вручную через **Run workflow**.
4. Адрес появится в **Settings → Pages** и в результате deployment. Для обычного репозитория он выглядит как `https://ИМЯ.github.io/ИМЯ-РЕПОЗИТОРИЯ/`.

Если основная ветка называется иначе, измените её имя в `.github/workflows/deploy.yml`. Папку `node_modules` загружать не нужно.

## Локальный запуск и сборка

Нужен Python 3. Из корня проекта:

```bash
python3 build.py
python3 -m http.server 8123
```

Откройте `http://localhost:8123/`. Сборка объединяет `src/template.html`, `src/styles.css` и файлы `src/js/` в самодостаточный `dist/index.html` и копию в корне проекта. Зависимостей для приложения нет.

## Ограничения

- Нет аккаунтов, облака, библиотеки ресурсов CapCut, AI-функций и многих профессиональных инструментов оригинала. Интерфейс и возможности не идентичны CapCut.
- Экспорт идёт примерно в реальном времени; оставляйте вкладку открытой и активной. Доступный формат — MP4 или WebM — зависит от поддержки MediaRecorder и кодеков браузером. Не все входные форматы, размеры и частоты кадров поддерживаются на каждом устройстве; большие проекты могут работать медленно.
- Проекты и медиа хранятся локально в конкретном браузере и могут быть удалены при очистке данных сайта или нехватке места. Храните оригиналы и экспортированные видео отдельно.
- JSON содержит структуру проекта, **но не сами файлы**. Он пригоден для восстановления при наличии тех же медиа в хранилище того же браузера; повторное связывание отсутствующих файлов при переносе на другое устройство пока не поддерживается. При загрузке проекта без исходников результат не будет полноценным.
- Одновременное отображение разных частей одного и того же исходного видео в нескольких клипах ограничено: они используют общий медиаэлемент. Некоторые переходы и наложения в такой ситуации могут выглядеть некорректно.
- На телефонах доступен сенсорный интерфейс. Скорость работы и экспорт зависят от устройства и браузера; на слабых устройствах большие проекты могут не поместиться в память. Доступ к микрофону требует разрешения и защищённого контекста (HTTPS или localhost).

## Проверки разработчика

В `tests/fixtures` лежат короткие тестовые файлы. Для E2E-теста нужны Node.js, Playwright и установленный Chromium:

```bash
npm install --no-save playwright@1.49.1
npx playwright install chromium
python3 build.py
python3 -m http.server 8123
# В другом терминале:
node tests/e2e.mjs
node tests/mobile.mjs
```

В Linux могут дополнительно понадобиться системные библиотеки Chromium (см. `npx playwright install-deps chromium`). Тесты проверяют основные сценарии и фактический экспорт, в том числе сенсорное управление на эмуляции телефона в Chromium. Это не доказывает работу всех комбинаций файлов, браузеров и устройств. Переменные `BASE_URL`, `ASSETS_DIR` и `SHOTS_DIR` позволяют изменить адрес, расположение тестовых медиа и скриншотов.
